# Documentation

`docs/` holds durable technical context that should survive beyond a code review or chat thread.

- `architecture/` describes the current system and its boundaries.
- `adr/` records consequential design decisions and alternatives.
- `runbooks/` provides executable operational recovery procedures.
- `postmortems/` captures incident evidence and preventive actions.

Documentation should describe implemented reality or clearly label proposed work. Link to source-controlled configuration and commands rather than copying values that will drift.
