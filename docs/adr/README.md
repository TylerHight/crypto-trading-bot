# Architecture Decision Records

Use this directory for decisions that materially affect interfaces, data ownership, operational risk, portability, cost, or future change.

Name records sequentially, for example `0001-use-kafka-for-event-transport.md`. Each ADR should contain:

1. Status and date.
2. Context and decision drivers.
3. Considered options.
4. Decision.
5. Consequences and follow-up work.

ADRs are append-only historical records. Supersede an old decision with a new ADR rather than rewriting the original rationale.
