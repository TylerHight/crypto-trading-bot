# Postmortems

This directory records simulated and real incidents as blameless learning documents.

Each postmortem should include impact, detection, a timestamped timeline, evidence, contributing conditions, root cause, recovery, what worked, what did not, and assigned preventive actions. Distinguish facts from hypotheses and include links to logs, tests, commits, runbooks, and ADRs when available.

Never include secrets, private exchange credentials, or unnecessary account data. Close preventive actions through normal tracked work rather than leaving them only in prose.
